# humanizer+ru

Русский редактор поверх humanizer: сначала нормальный русский язык, потом anti-AI эвристики.

Репозиторий пока называется `humanizer--ru`; переименование в `humanizer+ru` планируется отдельно. Внутреннее имя скилла временно остаётся `humanizer-ru`, чтобы не ломать установки.

## Зачем новый слой

Обычный humanizer решает задачу «убрать признаки нейросети». Это опасная целевая функция: если детектор считает длинное тире или `не X, а Y` подозрительным, редактор начинает ломать нормальную русскую пунктуацию и синтаксис.

`humanizer+ru` ставит приоритеты иначе:

`NORM > SEMANTICS > DISCOURSE > EDITING > AI-CALQUE > AUTHOR > detector score`

То есть:

- сначала исправляется русский язык;
- затем сохраняется точный смысл;
- затем фраза перестраивается по русской теме/реме и контексту;
- после этого убираются вода, канцелярит и кальки;
- только в конце оцениваются AI-паттерны;
- опционально применяется идиолект конкретного автора.

## Что изменилось принципиально

### Тире не запрещено

Тире — нормативный знак русской пунктуации. Нельзя заменять `—` дефисом `-` ради detector score. Повтор одного и того же тире-паттерна может получить предупреждение, сам знак — нет.

### `не X, а Y` не запрещено

Русское `не X, а Y` — нормальная заместительная конструкция. `не только X, но и Y` — тоже нормальный двойной союз.

Проверяется не форма, а функция: вторая часть должна добавлять реальную замену, контраст, новую информацию или переоценку.

### Двоеточие не режется ради «живости»

Если первая часть вводит перечисление, естественно:

> С такими курсами обычно две беды: либо чистая теория, либо пересказ пересказа.

А не автоматически:

> С такими курсами обычно две беды. Либо чистая теория. Либо пересказ пересказа.

### Порядок слов — не английский SVO

Русские падежи, согласование и управление кодируют синтаксические роли, поэтому порядок слов может работать на тему, рему, контраст и ритм.

> Паша любит Машу.
>
> Машу любит Паша.
>
> Паша Машу любит.

Редактор должен понимать контекст, а не переставлять слова «для разнообразия».

### Контекст можно не повторять

Русский естественно допускает неполные предложения и эллипсис:

> — Кого любит Паша?
> — Машу.

> Первый вариант дорогой. Второй — быстрее.

Humanizer не должен заставлять каждое предложение заново называть субъект, объект и предикат.

### Стоп-слова — сигналы, не запреты

Подход Норы Галь и информационного стиля используется для редактуры, но не заменяет грамматику. `же`, `всё-таки`, `просто`, `очень` или профессиональный англицизм могут выполнять реальную функцию.

## Архитектура

### Русский язык

[`references/russian-language.md`](references/russian-language.md)

Основной слой:

- морфология и порядок слов;
- тема и рема;
- контекстная экономия;
- эллипсис и нулевые элементы;
- противопоставление;
- двоеточия и тире;
- парцелляция;
- частицы;
- кальки и SVO-lock.

### Аудит старых правил

[`references/rule-audit.md`](references/rule-audit.md)

Все 34 старых паттерна пересмотрены. Главное:

- `не X, а Y` больше не hard ban;
- риторические вопросы не hard ban;
- математические знаки не hard ban вне жанрового контекста;
- правило трёх — только кластерный сигнал;
- повтор глагола не требует обязательного синонима;
- короткие фразы оцениваются по функции парцелляции;
- явная связка между каждым абзацем не обязательна.

### Нора Галь

[`references/nora-gal.md`](references/nora-gal.md)

Семантическая редактура:

- словесная алгебра;
- чужой голос;
- конфликт образов;
- сломанная сочетаемость;
- калька чужого синтаксиса;
- смысловое ударение.

### Информационный стиль

Идеи Ильяхова/Главреда используются как слой `EDITING`: стоп-слово вызывает проверку, а не автоматическое удаление.

После предоставления владельцем купленной книги можно добавить отдельный конспект правил с точными страницами; текущая ветка не заявляет, что полный текст книги уже разобран.

### Авторский профиль

[`references/author-profile.md`](references/author-profile.md)

Будущий `humanizer+ru+user` строит профиль по корпусу:

- частицы и дискурсивные маркеры;
- жаргон и англицизмы;
- эллипсис и нулевой субъект;
- ритм и длину фраз;
- самопоправки и скобки;
- способы возражать и усиливать мысль;
- локальную и поколенческую лексику;
- наблюдаемую степень категоричности и хеджирования по жанрам.

Ошибки автора сохраняются в профиле как наблюдения, но по умолчанию не имитируются.

```json
{
  "imitate_errors": false,
  "correct_norm_errors": true
}
```

Первый детерминированный экстрактор:

```bash
python3 scripts/profile_author.py corpus/ -o profile.json
```

Он считает наблюдаемые метрики. Семантические выводы модель должна подтверждать примерами из корпуса.

## Линтер v3

`scripts/lint.py` больше не пытается быть арбитром русского языка или AI-detector.

Он разделяет:

- `ARTIFACT` — технические следы чатбота; единственный автоматический гейт;
- `AI_PATTERN` — мягкие кальки и шаблоны;
- `STYLE_WARNING` — ритм, повтор конструкций, возможная неудачная парцелляция;
- `METRIC` — описательные метрики без нормативного порога.

Линтер больше не выдаёт псевдоточную формулу `errors*3 + warnings = AI score`.

Он специально не пытается regex-ом решить:

- тему и рему;
- правильность порядка слов;
- уместность `не X, а Y`;
- сочетаемость;
- субъект деепричастия во всех случаях;
- принадлежность фразы голосу автора.

Для JSON-вывода:

```bash
python3 scripts/lint.py --json text.md
```

Self-test:

```bash
python3 scripts/lint.py --self-test
```

## Evals

В репозитории теперь есть:

- `evals/evals.json` — исторические апстримные сценарии;
- `evals/fork-smoke.json` — прежние smoke-тесты форка;
- `evals/nora-gal.json` — семантический слой Норы Галь;
- [`evals/russian-language.json`](evals/russian-language.json) — 18 сценариев по русскому дискурсу.

Новый набор проверяет, среди прочего:

- сохранение нормативного противопоставления;
- двоеточие перед перечислением;
- однословный ответ с эллипсисом;
- тему/рему в разных контекстах;
- SVO-lock;
- лишние притяжательные местоимения;
- сохранение прагматических частиц;
- плохую и хорошую парцелляцию;
- профессиональный жаргон по аудитории;
- запрет имитировать авторские ошибки по умолчанию.
