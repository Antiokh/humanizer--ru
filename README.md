# humanizer--ru

Русский humanizer, который убирает AI-слоп, но не ломает русскую типографику и авторский голос ради антидетект-эвристики.

Это форк [smixs/humanizer-ru](https://github.com/smixs/humanizer-ru). Основа и большая часть логики остаются совместимыми с апстримом. Форк добавляет два осознанных расхождения: нормативное длинное тире «—» не считается автоматическим признаком нейросети, а после базового аудита текст проходит семантическую проверку по мотивам Норы Галь.

Два дефиса в названии отделяют этот вариант от апстрима и сразу показывают, что редакционная политика здесь отличается.

## Отличия форка

| Правило | `smixs/humanizer-ru` | `Antiokh/humanizer--ru` |
|---|---|---|
| Одно нормативное длинное тире | `ERROR`, требуется заменить | Допустимо |
| Частое шаблонное употребление тире | Ловится тем же полным запретом | `WARN` по плотности, решение принимает редактор |
| Замена тире дефисом `-` | Используется как anti-detection правило | Запрещена как типографическая ошибка |
| Семантическая проверка | 34 базовых паттерна | 34 базовых паттерна и 5 проверок по мотивам Норы Галь |

Апстрим сознательно оптимизирует текст под сокрытие AI-происхождения: длинное тире считается сильным маркером и запрещается целиком. Этот форк разделяет знак и паттерн. Само тире нормально для русского языка; подозрительным может быть его механическое повторение в каждом втором предложении.

Семантический слой проверяет то, что плохо ловится регулярными выражениями: пустые абстракции, чужой голос, конфликт образов, сломанную сочетаемость и кальку чужого синтаксиса. Эти проверки не являются бинарными запретами.

Вложенные кавычки и обычная капитализация заголовков уже приняты апстримом и не заявляются как отдельное преимущество форка.

## Что делает скилл

Скилл для AI-агентов: Claude Code, Codex, OpenClaw, Hermes и других систем, читающих `SKILL.md`. Он редактирует готовый русский текст:

- убирает канцелярит, воду и шаблонные AI-конструкции;
- сохраняет факты, цифры, авторскую позицию и странные живые детали;
- проверяет, принадлежит ли фраза голосу автора и звучит ли она по-русски;
- сначала проводит аудит, потом правит только найденные места;
- проверяет чистовик детерминированным Python-линтером;
- возвращает чистый текст без бессмысленного повторного переписывания.

В основном справочнике 34 паттерна: негативные параллелизмы, рекламные штампы, псевдоглубина, математическая нотация в прозе, рубленый драматизм, повтор глаголов, стопки несвязанных абзацев и другие признаки машинного текста.

Дополнение [`references/nora-gal.md`](references/nora-gal.md) вводит паттерны 35–39:

- словесная алгебра;
- не своим голосом;
- слова на ножах;
- вывихнутое сочетание;
- калька чужого синтаксиса.

## Установка

Через skills CLI:

```bash
npx skills add Antiokh/humanizer--ru
npx skills add Antiokh/humanizer--ru -g
```

Или вручную для Claude Code:

```bash
git clone https://github.com/Antiokh/humanizer--ru.git ~/.claude/skills/humanizer-ru
```

Внутреннее имя скилла пока сохраняется как `humanizer-ru`, поэтому существующие команды и установки не ломаются:

```text
/humanizer-ru

[ваш текст]
```

В любом агенте можно написать: «очеловечь этот текст», «убери воду», «очисти от признаков AI».

## Собрать свой Custom GPT

В папке [`gpt`](gpt/) лежит готовая конфигурация персонального редактора:

- [`gpt/SETUP.md`](gpt/SETUP.md) — поля GPT Builder, возможности и список Knowledge-файлов;
- [`gpt/INSTRUCTIONS.md`](gpt/INSTRUCTIONS.md) — готовые инструкции для поля Instructions;
- [`gpt/TESTS.md`](gpt/TESTS.md) — smoke-тесты для Preview перед публикацией.

Для Custom GPT включи Web Search, Canvas и Code Interpreter & Data Analysis. В Knowledge загрузи `references/patterns.md`, `references/nora-gal.md`, `knowledge/corrections.md`, `scripts/lint.py` и `SKILL.md`.

## Проверка

В репозитории есть:

- 18 апстримных eval-сценариев;
- `evals/fork-smoke.json` для типографической политики форка;
- `evals/nora-gal.json` для семантического слоя.

Пояснения находятся в [`evals/README.md`](evals/README.md).

Линтер `scripts/lint.py` работает на обычном Python 3 без зависимостей. Нормативное тире проходит проверку. Высокая плотность тире даёт предупреждение, но не блокирует результат автоматически. Семантические паттерны 35–39 оцениваются моделью по смыслу и не добавлены в жёсткий гейт.

```bash
python3 scripts/lint.py --self-test
python3 scripts/lint.py текст.md
```
