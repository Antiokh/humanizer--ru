# Eval-наборы

`evals/evals.json` унаследован от апстрима и считается историческим. Его assertions не имеют приоритета над русским языковым слоем.

Если старый eval требует:

- удалить нормативное тире;
- запретить `не X, а Y`;
- заменить любой риторический вопрос;
- разбить/склеить предложение только ради anti-detection;
- заменить профессиональный термин бытовым словом без учёта аудитории;

такой eval должен быть переписан, а не использоваться как критерий качества.

## Активные наборы

- `evals/fork-smoke.json` — исторический smoke-набор типографической политики;
- `evals/nora-gal.json` — семантический слой Норы Галь;
- `evals/russian-language.json` — основной набор русского языка и дискурса;
- `gpt/TESTS.md` — ручные сценарии Preview;
- `python3 scripts/lint.py --self-test` — поверхностный детерминированный линтер.

## Приоритет

`russian-language.json > nora-gal.json > fork-smoke.json > historical upstream evals`

При конфликте выигрывает сценарий, который сохраняет норму, смысл и естественную русскую конструкцию.

## Что проверяет russian-language.json

18 сценариев:

1. нормативное `не X, а Y` не считается AI-ошибкой;
2. противопоставление должно иметь смысловой прирост;
3. обобщение + перечисление восстанавливает двоеточие;
4. однословный ответ с контекстным эллипсисом сохраняется;
5. повтор существительного/сказуемого можно опустить;
6. тема/рема меняют порядок слов;
7. ударный ответ может стоять в начале после вопроса;
8. SVO-lock и повторное называние субъекта перестраиваются по контексту;
9. английская местоименная переэксплицитность убирается;
10. прагматическая частица не удаляется как мусор;
11. висячее деепричастие считается языковой проблемой;
12. бессмысленная парцелляция собирается обратно;
13. осмысленная парцелляция сохраняется;
14. единичный риторический вопрос разрешён;
15. стоп-слово не удаляется без проверки функции;
16. профессиональный жаргон оценивается по аудитории;
17. ошибки из author profile не имитируются по умолчанию;
18. при противительной оценке второй компонент может быть коммуникативно сильнее.

## Типографическая политика

Тире — знак русской пунктуации, а не detector token.

Линтер может показать высокую плотность тире как `STYLE_WARNING`, но не должен считать сам символ `—` ошибкой.

Дефис `-` не используется как механическая замена тире.

## Семантический слой

`evals/nora-gal.json` проверяет:

- конкретность без выдумывания фактов;
- соответствие голосу и ситуации;
- совместимость образов;
- сочетаемость;
- естественный русский синтаксис;
- смысловое ударение и степень уверенности.

## Как оценивать

Не используйте одну строку regex как judge для смыслового eval.

Для semantic/discourse eval нужен model judge или ручная проверка, которая получает:

- исходный текст;
- задачу;
- результат;
- expectations конкретного сценария.

Judge не должен видеть «правильный готовый текст», если это толкает его к дословному совпадению вместо проверки функции.

## Будущий корпусный eval

Следующий этап — собрать не только искусственные пары, но и корпус:

- хорошие человеческие тексты разных жанров;
- плохие человеческие тексты;
- сырые LLM-тексты;
- LLM после разных humanizer;
- намеренно литературные тексты;
- рабочие/технические тексты с профессиональным жаргоном;
- авторские корпуса для `humanizer+ru+user`.

Критерии качества должны измерять сохранение смысла и русского языка, а не вероятность прохождения внешнего AI-detector.
